# 犬舎ノート v13.1 ルール履歴・出産間隔対応版

## 今後の標準デザイン

`犬舎ノート_完成デザイン反映_v6_Android評価版.zip`に実装されたUIを、今後の開発における正式な最新基準版・標準デザインとして扱います。明示的なデザイン変更指示がない限り、現在の配色、フォント、文字サイズ、カード・ボタン・SVGアイコンの形状と配置、余白、下部ナビゲーション、ホームの固定操作領域、要対応カード構造、スマートフォン向けレイアウトを維持してください。新しい画面や部品は、この版の色、角丸、枠線、影、文字、アイコンのルールに合わせて追加します。

犬の世話をしながら、片手で日常記録を残すためのiPhone縦画面基準PWAです。日常記録から確認用帳簿を組み立てます。正式運用・正式帳票・法令適合を保証する版ではありません。

## ローカル起動と検証

Node.js 20以上とpnpmを用意してください。

```powershell
pnpm install --frozen-lockfile
pnpm typecheck
pnpm lint
pnpm test
pnpm build
pnpm preview
```

開発時は `pnpm dev` を使います。本番成果物は `dist/` です。コード読取または画像撮影時だけカメラ権限を要求します。

高精度OCRモデルはGitへ直接収録せず、`pnpm dev`または`pnpm build`の直前に、固定済み依存パッケージから`public/ocr/`へ自動配置します。これによりGitHubのファイル容量制限を避けながら、配布物には同じ高精度モデルが収録されます。

テストは`tests/*.test.js`だけを対象にします。GitHubへブラウザから上書きした際に旧版のルート直下テストが残っていても、Pagesのビルドへ混入しません。

## 実装済み

- 設定から交配年齢、出産回数、前回出産から次回交配までの期間、記録保存期間、繁殖台帳の任意項目を変更できるルール設定基盤
- ルールの適用開始日・根拠メモ・変更履歴を端末内に保存し、バックアップと復元の対象に含めるv13.1履歴管理
- ルール超過時は保存禁止にせず、確認警告を表示して人が最終判断する運用
- 保存期間を過ぎた記録件数の確認（自動削除は行わない）
- 犬の登録・検索・詳細4タブ、空欄を除外したマイクロチップ重複検出
- 1日2回の正常／異常点検。清掃、消毒、設備、頭数、犬の状態、その他を個別記録
- 体重、ワクチン、駆虫、治療・通院、投薬
- 1つの繁殖案件へ複数の交配日・方法・時刻・担当者・メモを追加、編集、削除
- 最初と最後の交配日から出産予定時期を自動計算し、獣医師等が確認した予定日・根拠も別途保存
- 妊娠確認、出産、父母ID付き子犬作成、重複出産防止、同腹表示
- お迎え予定の作成と完了、犬状態・履歴・帳簿への反映
- 種類・対象犬による履歴絞り込み
- 個体、繁殖、点検、取引、定期報告の縦型プレビュー、共通CSV出力、PDF保存・印刷
- 京都府（京都市を除く）の公式参考様式に合わせた個体管理帳簿、繁殖実施状況記録台帳、取引状況記録台帳、飼養施設・動物点検台帳、年度定期報告集計
- 事業所・登録番号・届出者・管轄保健所、品種・所有日・仕入元、販売先・法令遵守・現物確認・対面説明・死亡情報の記録
- IndexedDB保存、v1～v7からv8への自動移行（旧単一交配日・旧ルール設定も自動変換）、直前1操作だけのUndo
- 検証付きJSONバックアップ・復元（画像込み完全版／記録のみ軽量版）
- Manifest、Service Worker、オフラインアプリシェル、192/512pxアイコン
- ホームの要対応は最大5件。6件以上は「すべて表示」から専用一覧へ移動
- ホーム画面は承認済みデザイン見本に合わせ、生成り背景、白い要対応カード、種別アイコン、深緑の主ボタン、3項目ナビへ統一
- ホームの2つの記録ボタンは要対応件数にかかわらず下部ナビ直上へ固定し、要対応部分だけをスクロール
- 下部ナビは淡いセージ色の3ボタンとし、選択中は深緑背景と白いアイコン・文字で明確に表示する。影や下線は使用しない
- 要対応カード個別非表示、再読込後の維持、設定からの一括再表示
- 犬舎・ホーム・帳簿の3項目ナビゲーションと安定したSVGアイコン
- マイクロチップ番号のQR・バーコードライブ読取
- 書類画像の撮影・選択、長辺2400px以下への端末内圧縮、プレビュー、削除
- 保存画像の端末内高精度OCR（日本語＋英数字）、画像補正、信頼度表示、候補抽出、確認後の記録反映
- ワクチン証明書、マイクロチップ登録証明書、血統書、診療・治療関係、その他書類への分類

Undoスナップショットは永続データの外に保持するため、再読込後は取り消せません。Service Worker更新ではキャッシュだけを更新し、IndexedDBは削除しません。

要対応の×は予定や記録を削除せず、表示だけを`uiPreferences`へ保存します。ホームは最大5件を表示し、6件以上ある場合だけ「すべて表示」から全件の専用一覧へ移動できます。専用一覧でも×と該当記録への導線を利用できます。点検回数・日付、出産予定日・状態、お迎え予定日・状態、健康予定日が変われば別項目として再表示されます。設定の「閉じた要対応を再表示」で一括解除でき、非表示設定はバックアップにも含まれます。

マイクロチップ番号はカメラでQR・バーコードを読み取るか、手入力できます。カメラを拒否した場合も手入力を継続できます。書類画像と記録はこの端末内だけに保存され、外部へ送信されません。評価では架空データだけを使ってください。

保存済み画像は、犬詳細の「その他」から「文字を読み取る」を選ぶと端末内OCRを実行できます。日付、病院名、ワクチン名、15桁のマイクロチップ番号を候補として表示します。候補は必ず人が確認・修正してから保存し、OCRだけで既存記録を上書きしません。OCR本体と日本語・英語の高精度学習データは配布物に同梱し、Service Workerにも保存します。

## GitHub Pages

### プロジェクトPages（`ユーザー名.github.io/リポジトリ名/`）

Viteを `--base=./` でビルドするため、リポジトリ名に依存しない相対参照になります。リポジトリの Settings → Pages → Source を GitHub Actions に変更し、同梱の `.github/workflows/pages.yml` を利用します。`main`へのpushまたは手動実行で、型検査・lint・テスト・ビルド後に公開されます。

### ルートPages（`ユーザー名.github.io/`）

同じWorkflowをユーザーPagesリポジトリで使用できます。相対参照なので追加変更は不要です。

画面遷移はHistory APIの深いURLを使わない単一HTML構成のため、Pagesの404対策ファイルは不要です。公開操作やpushはこの成果物では実施していません。

### 既存`kennel-note`を更新する手順

1. 完全ZIPを展開し、直下に`README.md`と`package.json`があることを確認します。
2. GitHubの`kennel-note`リポジトリへ、展開内容を既存ファイルへ上書きする形で登録します。
3. `.github/workflows/pages.yml`も必ず登録します。Web画面やWindowsではドットで始まる`.github`が選択から漏れることがあるため、登録後にリポジトリ上で直接確認してください。
4. Actionsタブの`Deploy GitHub Pages`が自動実行され、緑のチェックになるまで待ちます。
5. [公開URL](https://calculationman-lab.github.io/kennel-note/)をAndroid Chromeで開き、新しい「要対応」ホームを確認します。

古い画面が残る場合は、まずホーム画面のアプリを完全終了して再起動し、次にChromeで公開URLを再読み込みしてください。それでも変わらない場合だけサイト設定でキャッシュを確認します。保存データを消す操作は最初の解決策にしないでください。

## Androidへのインストール

1. GitHub PagesのURLをAndroid Chromeで開く。
2. Chromeメニューから「アプリをインストール」または「ホーム画面に追加」を選ぶ。
3. ホーム画面の「犬舎ノート」から起動する。

## Android評価シナリオ

1. ホームで優先予定を確認する。
2. 1回目の正常点検を登録する。
3. 2回目の「異常・変更あり」を開き、項目を選んで登録する。
4. 犬を新規登録し、検索して詳細を開く。
5. 健康タブまたは記録メニューから、体重、ワクチン、駆虫、治療、投薬を登録する。
6. 交配で「＋交配日を追加」から3日分を登録し、予定期間を確認する。いったん編集画面へ戻り、日付の追加・修正・削除を確認する。
7. 妊娠確認、出産を順に登録し、子犬の父母情報を確認する。
8. お迎え予定を登録して完了する。
9. 履歴を種類と犬で絞り込む。
10. 繁殖実施状況記録台帳のCSV・PDFに全交配日と予定期間が出ることを確認する。
11. アプリを閉じて再起動し、データが残ることを確認する。
12. 設定から画像込みバックアップを書き出し、復元後も複数交配日が残ることを確認する。
13. 一度オンライン起動した後、機内モードで再起動・閲覧・記録する。

## 評価時の注意

- 架空データだけを使い、実在するオーナー情報や診療書類を入力しないでください。
- 保存先は現在のブラウザ・端末内です。AndroidとiPhoneは同期しません。
- Chromeのサイトデータ削除やアプリ削除で消える可能性があります。必要に応じてバックアップしてください。
- 自治体別正式帳票、クラウド同期は未実装です。

## バックアップ

設定からバージョン付きJSONを出力します。復元時は種別、バージョン、スキーマ、必須配列、犬ID重複、健康・お迎え記録の関連IDを検証し、犬と主な記録件数を表示してから現在データを上書きします。破損JSONは拒否します。
